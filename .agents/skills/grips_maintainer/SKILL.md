# Grips Application Overview

The `grips` application is a Django app designed to convert unstructured, dense text (like the background resources or chat memory) into a heavily structured, self-organizing **Knowledge Graph**. 

Unlike a simple RAG (Retrieval-Augmented Generation) system that just fetches chunks of text, `grips` models concepts and the explicit relationships between them.

## Core Models (`grips.models`)
- **Domain**: A broad categorization (e.g., "Causal Statistics", "HR Policies") that provides a stylistic guide for the LLM when extracting knowledge.
- **ConceptNode**: The fundamental building block (like a Wiki Page). It holds a title, narrative content (markdown explanation), and structured claims (JSON list).
- **KnowledgeEdge**: A directed edge between two `ConceptNode`s defining their relationship (e.g., `DEPENDS_ON`, `INCLUDES`, `EXEMPLIFIES`, `RELATED_TO`). Contains a textual `justification` for *why* the edge exists.

## The Map-Reduce Ingestion Pipeline (`grips.tasks`)
The ingestion pipeline is designed to extract knowledge hierarchically to prevent massive duplication and context-window exhaustion. 

### Level 1: Chunk-Level Extraction
- **Scope**: Runs per-document-chunk.
- **Goal**: Extracts raw concepts and edges found purely within that chunk. 
- **Side Effect**: Because it is isolated to single chunks, it frequently creates multiple distinct `ConceptNode` objects with the exact same `title` (e.g., five chunks all mention "Active Trail", resulting in five identical nodes). This causes "duplicate" edges in the database because they point to different chunk-level `ConceptNode` objects.

### Level 2: In-Domain Synthesis (Unify Overlaps)
- **Scope**: Runs across all concepts in a specific `Domain`.
- **Goal**: Scans for `ConceptNode`s with identical or highly similar titles/content. It uses the LLM to unify these duplicate chunk-level concepts into a single, canonical domain-level abstract concept, updating all associated `KnowledgeEdge`s to point to the canonical node.
- **Crucial Rule**: *Level 2 must be run to clean up the duplicates generated by Level 1.*

### Level 3: Cross-Domain Synthesis
- **Scope**: Runs across domains.
- **Goal**: Finds analogies or high-level abstract similarities between completely different domains (e.g., finding the structural similarities between "Neural Network Backpropagation" and "Organizational Feedback Loops").

## Automated Linting
Because LLMs can hallucinate or create illogical structures, `grips` employs background linters (`task_lint_concept_node`, `task_lint_knowledge_edge`):
1. **Concept Linting**: Ensures the `narrative_content` matches the `structured_claims` without contradictions.
2. **Edge Linting**: Validates that the `justification` truly supports the chosen `relationship_type` between the source and target concepts.

## Maintainer Guidelines
- **Do not bypass the Celery Task Queue**: Extraction and linting are extremely slow, high-latency LLM operations. All significant modifications to the graph should be deferred to Celery tasks (`tasks.py`).
- **Handle Duplicate Titles Carefully**: Remember that `ConceptNode.title` is intentionally NOT unique. Duplicates are a deliberate side effect of Level 1 ingestion, pending Level 2 synthesis. Do not attempt to enforce uniqueness on the title at the database level.
- **Administrative Interfaces**: All Celery workflows should have corresponding triggers inside `grips/admin.py` via standard Django admin actions. Ensure admin actions wrap tasks properly instead of passing task functions directly to `actions = []`.
